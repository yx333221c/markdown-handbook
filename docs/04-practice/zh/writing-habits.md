# 我写 Markdown 时认下的几条

> English: [en/writing-habits.md](../en/writing-habits.md)

下面是我自己写顺了的做法，不是谁定的规矩。每条后面跟一句缘由，你不同意可以照旧，至少知道我躲的是什么。

## 空行和标题

标题、列表、引用、围栏这些块级元素，前后都留空行。标题下面不空一行，有的解析器会把紧跟着的文字算进标题的上下文；GFM 规范 1.3 节把「块引用/标题前要不要空行」列成 Gruber 当年没回答的问题，说明这里真会出分歧。标题层级别跳，`#` 一篇只用一次，当文档标题。我见过这样的开头：

```markdown
# 部署说明
### 3.1 配置
正文第一行
```

改成下面这样，目录和屏幕阅读器读到的层级是连着的：

```markdown
# 部署说明

## 配置

正文第一行。
```

## 换行怎么折

有两种都能活的写法。一句占一行，`git diff` 里改动只落在那一句；按 80 列折行，窄窗口不用横向滚。代价也各自清楚：前者单行会很长，后者改一个词可能牵动好几行。都得记住软换行这件事——这样写：

```markdown
这一行写了一半
下一行接着写同一句
```

渲染出来是这个样子，中间合成一个空格，不是断行：

```text
这一行写了一半 下一行接着写同一句
```

真要断开，得靠行尾两个空格或行尾一个反斜杠。可这两个又常被 lint 当行尾空格清掉，所以选一种就别混用。

## 列表、图片、链接

列表嵌套我固定用两个空格缩进，不混 tab。GFM 规范 1.3 节里「子列表缩进几个空格」也是当年悬着的问题，混着写最容易在不同渲染器里错层。图片的 `alt` 写清画面里有什么：`![图片](./assets/login-error.png)` 等于没写，读屏的人只听到「图片」；换成 `![登录框下方的红色报错提示](./assets/login-error.png)` 才知道这张图在讲什么。仓库里的链接一律用相对路径，`[规范说明](../../03-spec/zh/commonmark.md)` 换台机器、换个克隆目录还能点开；写成 `[规范说明](/Users/me/markdown-handbook/docs/03-spec/zh/commonmark.md)` 就只在我这台机器上成立。

## 代码、`HTML`、表格

每个围栏代码块都标语言，哪怕只是 `text`。高亮是小事，标了之后 Pandoc 和文档站点才知道该怎么处理这一段。四个空格缩进的代码块我也一律换成围栏：缩进版没地方写语言名，而且「缩进代码块前要不要空行」在 GFM 1.3 节里同样是个问号。外层用 `~~~markdown` 是为了把围栏本身装进去：

~~~markdown
```bash
pandoc input.md -o output.html
```
~~~

原始 `HTML` 我尽量不碰，除非目标平台只认它——GFM 明确会禁止原始 `HTML`（`disallowed raw HTML`），写进去可能被过滤掉，白忙一场。表格列数一多就该拆，手机上横向滚到第四列基本没人看。

提交前我一定在目标渲染器里看一眼，哪怕只是 github.com 编辑框上方的 Preview 标签。源码读着顺，排版未必顺。
